### 1.1 APA ITU PROXY SERVER?

**Proxy Server** adalah sebuah server yang bertindak sebagai perantara (intermediary) antara perangkat klien dan server tujuan di internet. Proxy menerima permintaan dari klien, meneruskannya ke server tujuan, menerima respons dari server, lalu meneruskannya kembali ke klien.

**Bayangkan seperti ini:**

Kamu ingin membeli barang di toko. Daripada pergi langsung ke toko, kamu menyuruh asisten untuk pergi ke toko membelikan barang yang kamu inginkan. Asisten akan pergi ke toko, membeli barang, lalu membawanya kembali kepadamu. Dalam skenario ini, asisten bertindak seperti proxy server.

**Definisi Formal:**

Proxy server adalah sistem komputer atau aplikasi yang berfungsi sebagai perantara antara perangkat pengguna (klien) dan server tujuan di internet. Proxy menerima, memproses, dan meneruskan permintaan serta respons antara klien dan server.

**Istilah Penting:**

1. **Forward Proxy** - Proxy yang melayani permintaan dari klien internal ke internet
2. **Reverse Proxy** - Proxy yang melayani permintaan dari internet ke server internal
3. **Transparent Proxy** - Proxy yang tidak terlihat oleh klien
4. **Caching Proxy** - Proxy yang menyimpan data untuk akses lebih cepat

---

<span id="bab1-2"></span>

### 1.2 FUNGSI DAN MANFAAT PROXY SERVER

**Fungsi Utama Proxy Server:**

| No | Fungsi | Penjelasan |
|----|--------|------------|
| 1 | **Caching** | Menyimpan konten yang sering diakses untuk mempercepat akses |
| 2 | **Filtering** | Membatasi akses ke situs tertentu berdasarkan kebijakan |
| 3 | **Anonimitas** | Menyembunyikan IP asli klien dari server tujuan |
| 4 | **Keamanan** | Melindungi jaringan internal dari ancaman eksternal |
| 5 | **Kontrol Akses** | Mengatur siapa yang bisa mengakses apa |
| 6 | **Bandwidth Optimization** | Menghemat bandwidth dengan caching |
| 7 | **Logging** | Mencatat aktivitas akses internet |

---

**Manfaat Proxy Server:**

**1. Caching (Penyimpanan Sementara)**

Proxy menyimpan salinan konten yang sering diakses. Ketika pengguna meminta konten yang sama, proxy memberikan dari cache, tidak perlu mengunduh ulang dari internet.

**Manfaat:**
- Akses lebih cepat
- Menghemat bandwidth
- Mengurangi beban server tujuan

**Contoh:**
Jika 100 pengguna mengakses halaman yang sama, hanya pengguna pertama yang mengunduh dari internet. 99 pengguna berikutnya mendapat dari cache proxy.

---

**2. Filtering (Penyaringan Konten)**

Proxy dapat memblokir akses ke situs-situs tertentu berdasarkan:
- URL
- Kata kunci
- Kategori
- Waktu

**Manfaat:**
- Produktivitas karyawan meningkat
- Keamanan meningkat
- Kebijakan perusahaan terimplementasi

---

**3. Anonimitas (Kerahasiaan)**

Proxy menyembunyikan IP asli pengguna, sehingga pengguna dapat mengakses internet secara anonim.

**Manfaat:**
- Privasi terjaga
- Sulit dilacak
- Bisa mengakses konten yang dibatasi geografis

---

**4. Keamanan**

Proxy bertindak sebagai lapisan keamanan tambahan antara jaringan internal dan internet.

**Manfaat:**
- Melindungi dari serangan langsung
- Dapat melakukan scanning malware
- Mencegah akses ke situs berbahaya

---

**5. Kontrol Akses**

Proxy dapat mengatur siapa yang bisa mengakses internet dan apa yang bisa diakses.

**Manfaat:**
- Otentikasi pengguna
- Pembatasan berdasarkan grup/departemen
- Penjadwalan akses

---

**6. Logging dan Monitoring**

Proxy mencatat semua aktivitas akses internet.

**Manfaat:**
- Audit akses
- Analisis penggunaan bandwidth
- Deteksi aktivitas mencurigakan
- Kepatuhan regulasi

### 1.3 JENIS-JENIS PROXY SERVER

---

**A. Berdasarkan Orientasi**

**1. Forward Proxy**

Forward proxy adalah proxy yang melayani permintaan dari klien internal ke internet.

**Ilustrasi:**
```
[Klien] → [Forward Proxy] → [Internet] → [Server Tujuan]
```

**Karakteristik:**
- Berada di sisi klien
- Mengakses internet untuk klien
- Klien tahu tentang proxy (atau tidak)

**Penggunaan:**
- Jaringan perusahaan
- Sekolah/kampus
- ISP

---

**2. Reverse Proxy**

Reverse proxy adalah proxy yang melayani permintaan dari internet ke server internal.

**Ilustrasi:**
```
[Klien Internet] → [Reverse Proxy] → [Server Internal]
```

**Karakteristik:**
- Berada di sisi server
- Melindungi server internal
- Klien tidak tahu tentang server internal

**Penggunaan:**
- Load balancing
- Keamanan server
- Web server besar

---

**B. Berdasarkan Visibilitas**

**1. Transparent Proxy**

Proxy yang tidak terlihat oleh klien. Klien tidak perlu melakukan konfigurasi apapun.

**Karakteristik:**
- Klien tidak tahu ada proxy
- Konfigurasi di sisi jaringan (router/switch)
- Intercept traffic secara otomatis

**Penggunaan:**
- Jaringan perusahaan
- ISP
- Sekolah

---

**2. Non-Transparent Proxy (Explicit Proxy)**

Proxy yang terlihat oleh klien. Klien harus mengkonfigurasi browser atau aplikasi untuk menggunakan proxy.

**Karakteristik:**
- Klien tahu ada proxy
- Harus konfigurasi manual
- Bisa menggunakan autentikasi

**Penggunaan:**
- Organisasi yang membutuhkan kontrol ketat
- Pengguna yang membutuhkan anonimitas

---

**C. Berdasarkan Fungsi**

**1. Caching Proxy**

Proxy yang menyimpan konten untuk akses lebih cepat.

**Contoh:**
- Squid (Linux)
- Nginx caching
- Varnish

---

**2. Web Proxy**

Proxy khusus untuk lalu lintas HTTP/HTTPS.

**Contoh:**
- Squid
- Apache
- Nginx

---

**3. SOCKS Proxy**

Proxy yang bekerja di level sesi (layer 5). Mendukung berbagai protokol.

**Contoh:**
- Dante
- Shadowsocks

---

**4. Application Proxy**

Proxy khusus untuk aplikasi tertentu.

**Contoh:**
- FTP Proxy
- SMTP Proxy
- DNS Proxy

---

### 1.4 CARA KERJA PROXY SERVER

**Proses Kerja Forward Proxy:**

```
    [Klien]          [Proxy]          [Internet]          [Server]
       │                │                  │                  │
       │ 1. HTTP Request│                  │                  │
       │───────────────>│                  │                  │
       │                │ 2. Cek Cache     │                  │
       │                │ (Jika ada,       │                  │
       │                │  kirim dari cache)                  │
       │                │                  │                  │
       │                │ 3. Forward Request│                 │
       │                │─────────────────>│─────────────────>│
       │                │                  │                  │
       │                │                  │ 4. HTTP Response │
       │                │<─────────────────│<─────────────────│
       │                │                  │                  │
       │                │ 5. Cache Response│                  │
       │                │                  │                  │
       │ 6. Response    │                  │                  │
       │<───────────────│                  │                  │
```

**Langkah-langkah Detail:**

**Langkah 1: Klien Mengirim Request**
- Klien mengirim request HTTP ke proxy
- Proxy menerima request

**Langkah 2: Proxy Cek Cache**
- Proxy memeriksa apakah konten ada di cache
- Jika ada dan masih valid, kirim dari cache (langsung ke langkah 6)
- Jika tidak ada, lanjut ke langkah 3

**Langkah 3: Proxy Forward Request**
- Proxy meneruskan request ke server tujuan
- Proxy bertindak sebagai klien untuk server tujuan

**Langkah 4: Server Merespon**
- Server tujuan mengirim respons ke proxy
- Proxy menerima respons

**Langkah 5: Proxy Cache Response**
- Proxy menyimpan respons di cache
- Untuk permintaan berikutnya, response akan diambil dari cache

**Langkah 6: Proxy Kirim ke Klien**
- Proxy meneruskan respons ke klien
- Klien menerima respons

---

**Proses Kerja Reverse Proxy:**

```
    [Klien]          [Reverse Proxy]     [Server 1]
       │                    │                 │
       │ 1. Request         │                 │
       │───────────────────>│                 │
       │                    │ 2. Pilih Server │
       │                    │ (Load Balancing)│
       │                    │                 │
       │                    │ 3. Forward      │
       │                    │────────────────>│
       │                    │                 │
       │                    │ 4. Response     │
       │                    │<────────────────│
       │                    │                 │
       │ 5. Response        │                 │
       │<───────────────────│                 │
```

### 1.5 KELEBIHAN DAN KEKURANGAN PROXY SERVER

**Kelebihan Proxy Server:**

| No | Kelebihan | Penjelasan |
|----|-----------|------------|
| 1 | **Menghemat Bandwidth** | Caching mengurangi download berulang |
| 2 | **Akses Lebih Cepat** | Konten di cache diakses lebih cepat |
| 3 | **Keamanan Meningkat** | Perlindungan dari ancaman eksternal |
| 4 | **Kontrol Akses** | Membatasi akses ke situs tertentu |
| 5 | **Anonimitas** | Menyembunyikan IP asli |
| 6 | **Logging dan Monitoring** | Mencatat aktivitas akses |
| 7 | **Load Balancing** | Mendistribusikan beban ke beberapa server |
| 8 | **Filtering Konten** | Memblokir konten berbahaya |

---

**Kekurangan Proxy Server:**

| No | Kekurangan | Penjelasan |
|----|------------|------------|
| 1 | **Single Point of Failure** | Jika proxy down, semua akses internet terhenti |
| 2 | **Bottleneck** | Proxy bisa menjadi titik kemacetan |
| 3 | **Latency** | Menambah waktu response (kecuali cache) |
| 4 | **Kompleksitas** | Konfigurasi dan maintenance membutuhkan keahlian |
| 5 | **Cache Stale** | Cache bisa kedaluwarsa, memberikan konten usang |
| 6 | **SSL Issues** | HTTPS dapat menyulitkan caching dan filtering |
| 7 | **Biaya** | Membutuhkan hardware dan software tambahan |

### 1.8 KONFIGURASI DASAR SQUID

**A. Konfigurasi Dasar (Minimal)**

Edit file `/etc/squid/squid.conf`:

```conf
# Port yang digunakan
http_port 3128

# Interface yang digunakan (opsional)
http_port 192.168.1.100:3128

# Mengizinkan akses dari jaringan lokal
acl localnet src 192.168.1.0/24
acl localnet src 10.0.0.0/8
acl localnet src 172.16.0.0/12

# Mengizinkan akses
http_access allow localnet
http_access deny all

# Lokasi cache
cache_dir ufs /var/spool/squid 1000 16 256

# Memory cache
cache_mem 256 MB

# Logging
access_log /var/log/squid/access.log
```

**Penjelasan Konfigurasi:**

| Parameter | Fungsi |
|-----------|--------|
| `http_port 3128` | Port yang digunakan proxy |
| `acl localnet` | Mendefinisikan ACL untuk jaringan lokal |
| `http_access allow localnet` | Mengizinkan akses dari jaringan lokal |
| `http_access deny all` | Menolak semua akses lainnya |
| `cache_dir` | Lokasi cache (format: tipe lokasi size) |
| `cache_mem` | Memory yang digunakan untuk cache |

---

**B. Restart Squid**

```bash
# Cek konfigurasi (pastikan tidak ada error)
sudo squid -k parse

# Restart Squid
sudo systemctl restart squid

# Cek status
sudo systemctl status squid
```

---

**C. Konfigurasi Klien untuk Menggunakan Proxy**

**Windows:**
1. Buka Settings → Network & Internet → Proxy
2. Aktifkan "Use a proxy server"
3. Isi Address: `192.168.1.100` dan Port: `3128`
4. Klik Save

**Linux (Gnome):**
1. Buka Settings → Network → Proxy
2. Pilih "Manual"
3. Isi HTTP Proxy: `192.168.1.100:3128`
4. Terapkan

**Browser (Manual):**
1. Buka browser
2. Settings → Network Settings
3. Pilih "Manual proxy configuration"
4. Isi HTTP Proxy: `192.168.1.100` Port: `3128`

### 1.9 KONFIGURASI ACCESS CONTROL LIST (ACL)

ACL digunakan untuk mengontrol akses berdasarkan berbagai kriteria:

**A. Berdasarkan IP Address**

```conf
# Mendefinisikan ACL berdasarkan IP
acl ip_IT src 192.168.1.0/24
acl ip_HRD src 192.168.2.0/24
acl ip_Marketing src 192.168.3.0/24

# Mengizinkan akses
http_access allow ip_IT
http_access allow ip_HRD
http_access deny all
```

---

**B. Berdasarkan Domain/URL**

```conf
# Memblokir akses ke situs tertentu
acl blocked_sites dstdomain .facebook.com
acl blocked_sites dstdomain .twitter.com
acl blocked_sites dstdomain .youtube.com

# Menolak akses
http_access deny blocked_sites

# Mengizinkan akses ke domain tertentu
acl allowed_sites dstdomain .kemdikbud.go.id
http_access allow allowed_sites
```

---

**C. Berdasarkan Kata Kunci (URL Path)**

```conf
# Memblokir akses berdasarkan kata kunci
acl bad_keywords url_regex -i porn
acl bad_keywords url_regex -i gambling

http_access deny bad_keywords
```

---

**D. Berdasarkan Waktu**

```conf
# Mendefinisikan waktu kerja
acl working_time time MTWHF 08:00-17:00

# Hanya izinkan akses di waktu kerja
http_access allow localnet working_time
http_access deny all
```

---

**E. Berdasarkan Protokol**

```conf
# Hanya izinkan HTTP dan HTTPS
acl SSL_ports port 443
acl Safe_ports port 80
acl Safe_ports port 443

http_access deny !Safe_ports
http_access allow localnet
```

---

**F. Berdasarkan Metode HTTP**

```conf
# Hanya izinkan GET dan POST
acl allowed_methods method GET
acl allowed_methods method POST

http_access allow allowed_methods
http_access deny all
```

---

**G. Kombinasi ACL**

```conf
# Kombinasi beberapa kondisi
acl jam_kerja time MTWHF 08:00-17:00
acl departemen_IT src 192.168.1.0/24
acl situs_terlarang dstdomain .facebook.com

# Hanya IT yang bisa akses, jam kerja, tapi tidak ke facebook
http_access allow departemen_IT jam_kerja !situs_terlarang
http_access deny all
```

### 1.10 KONFIGURASI TRANSPARENT PROXY

Transparent proxy adalah proxy yang tidak terlihat oleh klien. Klien tidak perlu melakukan konfigurasi apapun.

**Langkah 1: Konfigurasi Squid**

Edit `/etc/squid/squid.conf`:

```conf
# Port untuk transparent proxy
http_port 3128 intercept

# Atau dengan interface tertentu
http_port 192.168.1.100:3128 intercept

# ACL untuk transparent proxy
acl transparent src 192.168.1.0/24
http_access allow transparent

# DNS
dns_nameservers 8.8.8.8 1.1.1.1
```

---

**Langkah 2: Konfigurasi iptables (Redirect Traffic)**

```bash
# Mengaktifkan IP forwarding
echo 1 > /proc/sys/net/ipv4/ip_forward

# Atau permanen
sudo sysctl -w net.ipv4.ip_forward=1

# Redirect HTTP traffic (port 80) ke Squid (port 3128)
sudo iptables -t nat -A PREROUTING -i eth0 -p tcp --dport 80 -j REDIRECT --to-port 3128

# Untuk HTTPS (jika ingin intercept)
sudo iptables -t nat -A PREROUTING -i eth0 -p tcp --dport 443 -j REDIRECT --to-port 3128

# Simpan aturan
sudo iptables-save > /etc/iptables/rules.v4
```

---

**Langkah 3: Restart Squid**

```bash
sudo systemctl restart squid
```

---

**Langkah 4: Verifikasi**

```bash
# Cek traffic
sudo tail -f /var/log/squid/access.log

# Tes dari klien (tanpa konfigurasi proxy)
# Buka browser, akses situs, lihat log
```

### 1.13 ANALISIS MASALAH PADA PROXY SERVER

**Masalah 1: Proxy Tidak Bisa Diakses**

| Gejala | Penyebab | Solusi |
|--------|----------|--------|
| Browser menampilkan error proxy | Squid tidak berjalan | Start Squid |
| Koneksi timeout | Port 3128 terblokir | Cek firewall |
| Connection refused | Squid tidak mendengar port | Cek konfigurasi http_port |


**Masalah 2: Akses Ditolak**

| Gejala | Penyebab | Solusi |
|--------|----------|--------|
| "Access Denied" | ACL tidak mengizinkan | Perbaiki ACL |
| Autentikasi gagal | Password salah | Reset password |
| Waktu akses diluar jam kerja | Time ACL | Perbaiki time ACL |

**Solusi:**
```bash
# Cek log untuk melihat penolakan
```

**Masalah 3: Cache Tidak Bekerja**

| Gejala | Penyebab | Solusi |
|--------|----------|--------|
| Akses selalu dari internet | Cache directory tidak ada | Buat cache directory |
| Akses lambat | Cache directory penuh | Bersihkan cache |
| Konten tidak di-cache | Konfigurasi cache salah | Perbaiki cache_dir |

**Solusi:**
```bash

# Bersihkan cache
```

---

**Masalah 4: Koneksi Lambat**

| Gejala | Penyebab | Solusi |
|--------|----------|--------|
| Akses internet lambat | Bandwidth terbatas | Optimasi bandwidth |
| Proxy menjadi bottleneck | Server kurang spek | Upgrade hardware |
| Terlalu banyak koneksi | Banyak pengguna | Tambah resource |

---

**Masalah 5: Transparent Proxy Tidak Bekerja**

| Gejala | Penyebab | Solusi |
|--------|----------|--------|
| Traffic tidak di-redirect | iptables tidak aktif | Cek iptables |
| Proxy tidak intercept | Squid tidak di intercept mode | Tambah "intercept" |

**Solusi:**

### 2.1 APA ITU MANAJEMEN BANDWIDTH?

**Manajemen Bandwidth** adalah proses mengatur dan mengontrol penggunaan bandwidth jaringan untuk memastikan penggunaan yang efisien dan adil. Manajemen bandwidth bertujuan untuk mengoptimalkan kinerja jaringan dengan mengalokasikan sumber daya sesuai kebutuhan.

**Bayangkan seperti ini:**

Bayangkan jalan raya dengan banyak kendaraan. Tanpa manajemen lalu lintas, semua kendaraan akan macet. Dengan manajemen lalu lintas, ada jalur khusus untuk bus (prioritas tinggi), lampu lalu lintas (pengaturan), dan pembatasan kecepatan (pembatasan). Manajemen bandwidth bekerja seperti manajemen lalu lintas untuk data di jaringan.

**Definisi Formal:**

Manajemen bandwidth adalah serangkaian teknik dan mekanisme yang digunakan untuk mengontrol, mengatur, dan mengoptimalkan penggunaan bandwidth jaringan. Tujuannya adalah untuk memastikan bahwa aplikasi dan pengguna mendapatkan sumber daya yang diperlukan dengan adil dan efisien.

**Istilah Penting:**

1. **Bandwidth** - Kapasitas maksimum transfer data
2. **Throughput** - Transfer data aktual
3. **Latency** - Waktu tunda pengiriman data
4. **Jitter** - Variasi latency
5. **Packet Loss** - Paket yang hilang selama pengiriman

---

<span id="bab2-2"></span>

### 2.2 MENGAPA MANAJEMEN BANDWIDTH DIPERLUKAN?

**1. Keterbatasan Bandwidth**

Bandwidth internet terbatas. Tanpa manajemen, beberapa pengguna atau aplikasi dapat menghabiskan semua bandwidth.

**2. Kebutuhan Berbeda**

Aplikasi yang berbeda memiliki kebutuhan yang berbeda:
- VoIP: membutuhkan latency rendah
- Streaming video: membutuhkan bandwidth besar
- Email: membutuhkan bandwidth kecil
- Download file: membutuhkan bandwidth besar

**3. Fairness**

Semua pengguna harus mendapatkan akses yang adil ke bandwidth yang tersedia.

**4. Prioritas Aplikasi Bisnis**

Aplikasi bisnis penting harus mendapatkan prioritas dibandingkan aplikasi hiburan.

**5. Penghematan Biaya**

Dengan manajemen bandwidth, perusahaan dapat mengoptimalkan penggunaan bandwidth yang sudah dibeli.

**6. Keamanan**

Mencegah serangan yang membanjiri jaringan (DDoS).

**7. SLA (Service Level Agreement)**

Memenuhi janji layanan kepada pelanggan.

---

<span id="bab2-3"></span>

### 2.3 KONSEP DASAR BANDWIDTH

**A. Satuan Bandwidth**

| Satuan | Nilai | Penggunaan |
|--------|-------|------------|
| bps | 1 bit per detik | Sangat kecil |
| Kbps | 1.000 bps | Modem dial-up |
| Mbps | 1.000.000 bps | Internet rumahan |
| Gbps | 1.000.000.000 bps | Jaringan perusahaan |

---

**B. Bandwidth vs Throughput**

| Aspek | Bandwidth | Throughput |
|-------|-----------|------------|
| Definisi | Kapasitas maksimum | Transfer aktual |
| Satuan | bps, Mbps, Gbps | bps, Mbps, Gbps |
| Faktor | Spesifikasi teknis | Kondisi jaringan |
| Contoh | 100 Mbps | 85 Mbps |

---

**C. Faktor yang Mempengaruhi Bandwidth**

1. **Kualitas Koneksi** - Fiber > Cable > DSL
2. **Jarak** - Semakin jauh, semakin rendah
3. **Jumlah Pengguna** - Semakin banyak, semakin terbagi
4. **Aplikasi** - Streaming, download, gaming
5. **Waktu** - Jam sibuk vs jam sepi

---

**D. Perhitungan Bandwidth**

```
Contoh:
1 GB = 1024 MB = 8.192 Mb
Untuk mendownload file 1 GB dengan kecepatan 100 Mbps:
Waktu = 8.192 Mb / 100 Mbps = 81.92 detik ≈ 1.36 menit
```

<span id="bab2-4"></span>

### 2.4 TEKNIK MANAJEMEN BANDWIDTH

**1. Traffic Shaping (Pembentukan Lalu Lintas)**

Mengatur kecepatan data sesuai batas yang ditentukan.

```
Karakteristik:
- Data di-buffer/ditahan
- Smoothing traffic
- Mengurangi burst

Contoh: Limit download ke 1 Mbps
```

**2. Traffic Policing (Penegakan Lalu Lintas)**

Menolak atau menjatuhkan paket yang melebihi batas.

```
Karakteristik:
- Paket berlebih di-drop
- Strict enforcement
- Tanpa buffer

Contoh: Drop paket jika melebihi 1 Mbps
```

**3. Traffic Prioritization (Prioritas Lalu Lintas)**

Memberikan prioritas pada traffic tertentu.

```
Karakteristik:
- High priority vs low priority
- QoS
- Application-aware

Contoh: VoIP mendapat prioritas tertinggi
```

**4. Traffic Filtering (Penyaringan Lalu Lintas)**

Memblokir atau mengizinkan traffic berdasarkan kriteria.

```
Karakteristik:
- Block/allow berdasarkan:
  - Port
  - IP
  - Protocol
  - Application

Contoh: Blokir torrent
```

<span id="bab2-5"></span>

### 2.5 QUALITY OF SERVICE (QoS)

**Apa Itu QoS?**

QoS adalah serangkaian teknologi yang digunakan untuk mengelola lalu lintas jaringan dan memastikan performa untuk aplikasi penting.

**Tujuan QoS:**

1. **Prioritaskan** - Traffic penting mendapat prioritas
2. **Batas** - Traffic dibatasi sesuai kebutuhan
3. **Jaminan** - Performa minimal terjamin
4. **Efisiensi** - Penggunaan bandwidth optimal

**Parameter QoS:**

| Parameter | Deskripsi | Nilai Baik |
|-----------|-----------|------------|
| Bandwidth | Kecepatan transfer | Sesuai kebutuhan |
| Latency | Waktu tunda | < 150 ms |
| Jitter | Variasi latency | < 30 ms |
| Packet Loss | Paket hilang | < 1% |

---

**Model QoS:**

**1. Best Effort**
- Tidak ada jaminan
- Standar internet

**2. Integrated Services (IntServ)**
- Reservasi sumber daya
- RSVP

**3. Differentiated Services (DiffServ)**
- Klasifikasi traffic
- DS field (DSCP)

---

**Layanan QoS:**

| Layanan | Bandwidth | Latency | Jitter | Packet Loss |
|---------|-----------|---------|--------|-------------|
| VoIP | 64-128 Kbps | < 150 ms | < 30 ms | < 1% |
| Video Conference | 384 Kbps - 4 Mbps | < 200 ms | < 50 ms | < 2% |
| Streaming Video | 1-10 Mbps | < 400 ms | < 100 ms | < 5% |
| Web Browsing | Variabel | < 1000 ms | - | < 10% |
| Email | Kecil | < 2000 ms | - | < 20% |
| Download | Besar | Tidak kritis | - | - |

<span id="bab2-6"></span>

### 2.6 TRAFFIC SHAPING VS TRAFFIC POLICING

**Traffic Shaping (Pembentukan):**

```
Karakteristik:
- Data di-buffer
- Smoothing traffic
- Menghaluskan burst
- Mengurangi packet loss

Keunggulan:
- Lebih halus
- Tidak menjatuhkan paket
- Lebih adil

Kekurangan:
- Menambah latency
- Membutuhkan buffer
```

**Traffic Policing (Penegakan):**

```
Karakteristik:
- Paket berlebih di-drop
- Strict enforcement
- Tanpa buffer
- Penegakan keras

Keunggulan:
- Tidak menambah latency
- Sederhana
- Efisien

Kekurangan:
- Paket hilang
- Keras
- Tidak adil untuk burst
```

**Perbandingan:**

| Aspek | Traffic Shaping | Traffic Policing |
|-------|-----------------|------------------|
| Buffer | Ya | Tidak |
| Packet Loss | Minimal | Ada |
| Latency | Bertambah | Tidak bertambah |
| Burst Traffic | Dihaluskan | Dijatuhkan |
| Penggunaan | Umum | Strict enforcement |
| Kompleksitas | Lebih kompleks | Sederhana |

<span id="bab2-7"></span>

### 2.7 PRIORITY QUEUING (PQ)

**Apa Itu Priority Queuing?**

PQ adalah metode queuing di mana traffic dibagi menjadi beberapa antrian dengan prioritas berbeda. Traffic dengan prioritas lebih tinggi dilayani terlebih dahulu.

**Cara Kerja PQ:**

```
[High Priority] → Server 1 → Server 2 → Server 3 → Server 4
[Medium Priority] → Server 1 → Server 2 → Server 3 → Server 4
[Low Priority] → Server 1 → Server 2 → Server 3 → Server 4
```

**Ilustrasi:**

```
Antrian 1 (High)  : ████████████████████████████ (dilayani dulu)
Antrian 2 (Medium): ████████████████████████████ (dilayani kedua)
Antrian 3 (Low)   : ████████████████████████████ (dilayani terakhir)
```

**Keunggulan PQ:**
- Sederhana
- Traffic prioritas tinggi terjamin
- Mudah dikonfigurasi

**Kekurangan PQ:**
- Traffic prioritas rendah bisa kelaparan
- Tidak adil
- Tidak efisien

---

<span id="bab2-8"></span>

### 2.8 WEIGHTED FAIR QUEUING (WFQ)

**Apa Itu WFQ?**

WFQ adalah metode queuing yang memberikan bobot (weight) pada setiap antrian. Antrian dengan bobot lebih tinggi mendapatkan bandwidth lebih banyak.

**Cara Kerja WFQ:**

```
Flow 1 (Weight 10) → 10 unit bandwidth
Flow 2 (Weight 20) → 20 unit bandwidth
Flow 3 (Weight 30) → 30 unit bandwidth
Flow 4 (Weight 40) → 40 unit bandwidth
```

**Ilustrasi:**

```
     │ ████ │ ████████ │ ████████████ │ ████████████████ │
     │ Flow │ Flow 2   │ Flow 3       │ Flow 4           │
     │ (10) │ (20)     │ (30)         │ (40)             │
```

**Keunggulan WFQ:**
- Adil
- Tidak ada yang kelaparan
- Efisien untuk variasi flow

**Kekurangan WFQ:**
- Kompleks
- Tidak untuk prioritas tinggi
- Overhead lebih besar

---

<span id="bab2-9"></span>

### 2.9 CLASS-BASED WEIGHTED FAIR QUEUING (CBWFQ)

**Apa Itu CBWFQ?**

CBWFQ adalah pengembangan dari WFQ yang memungkinkan klasifikasi traffic sebelum queuing.

**Cara Kerja CBWFQ:**

```
[Class 1: VoIP] → Weight 30 → Bandwidth 30%
[Class 2: Video] → Weight 20 → Bandwidth 20%
[Class 3: Data] → Weight 10 → Bandwidth 10%
[Class 4: Default] → Weight 40 → Bandwidth 40%
```

**Ilustrasi:**

```
Traffic → Classifier → [VoIP] → CBWFQ → Output
                     → [Video] → CBWFQ → Output
                     → [Data] → CBWFQ → Output
```

**Keunggulan CBWFQ:**
- Klasifikasi traffic
- Adil dalam class
- Kontrol lebih baik

**Kekurangan CBWFQ:**
- Kompleks
- Membutuhkan konfigurasi yang baik
- Overhead

---

<span id="bab2-10"></span>

### 2.10 LOW LATENCY QUEUING (LLQ)

**Apa Itu LLQ?**

LLQ adalah kombinasi PQ dan CBWFQ. LLQ menyediakan antrian prioritas untuk traffic latency-sensitive (seperti VoIP).

**Cara Kerja LLQ:**

```
[Priority Queue] → VoIP → Dilayani dulu
[Class 1] → Video → CBWFQ
[Class 2] → Data → CBWFQ
[Class 3] → Default → CBWFQ
```

**Ilustrasi:**

```
Traffic → [VoIP] → Priority Queue (80% bandwidth)
       → [Video] → Class 1
       → [Data]  → Class 2
       → [Other] → Default
```

**Keunggulan LLQ:**
- Prioritas untuk latency-sensitive
- Fleksibel
- Kombinasi PQ dan CBWFQ

**Kekurangan LLQ:**
- Kompleksitas tinggi
- Memerlukan perencanaan yang baik

### 3.1 APA ITU LOAD BALANCING?

**Load Balancing** adalah teknik untuk mendistribusikan beban kerja atau lalu lintas jaringan ke beberapa server atau jalur koneksi. Tujuannya adalah untuk mengoptimalkan penggunaan sumber daya, memaksimalkan throughput, meminimalkan waktu respons, dan menghindari overload pada satu server atau jalur.

**Bayangkan seperti ini:**

Bayangkan sebuah restoran dengan banyak pelanggan. Jika hanya ada satu kasir, semua pelanggan akan mengantri panjang. Dengan menambah beberapa kasir, pelanggan dapat dilayani lebih cepat. Load balancing bekerja seperti menambah kasir untuk melayani pelanggan secara merata.

**Definisi Formal:**

Load balancing adalah proses mendistribusikan lalu lintas jaringan atau beban aplikasi ke beberapa server atau jalur koneksi secara efisien dan adil. Load balancer bertindak sebagai perantara antara klien dan server, meneruskan permintaan ke server yang paling sesuai.

**Istilah Penting:**

1. **Load Balancer** - Perangkat atau software yang melakukan load balancing
2. **Server Farm** - Kumpulan server yang melayani aplikasi
3. **Backend Server** - Server yang menerima traffic dari load balancer
4. **Health Check** - Pengecekan status server
5. **Session Persistence** - Menjaga sesi pengguna ke server yang sama

---

<span id="bab3-2"></span>

### 3.2 MENGAPA LOAD BALANCING DIPERLUKAN?

**1. Skalabilitas**

Load balancing memungkinkan penambahan server secara horizontal (scale-out) untuk menangani peningkatan beban.

**2. Availability (Ketersediaan)**

Jika satu server down, load balancer akan mengalihkan traffic ke server lain yang masih sehat. Ini meningkatkan uptime.

**3. Redundansi**

Tidak ada single point of failure. Jika satu server mati, yang lain tetap berjalan.

**4. Performa**

Beban didistribusikan ke beberapa server, meningkatkan response time.

**5. Maintenance**

Server bisa di-maintenance (update, upgrade) secara bergantian tanpa downtime.

**6. Optimalisasi Sumber Daya**

Penggunaan sumber daya lebih efisien karena beban terdistribusi secara merata.

**7. Geographical Distribution**

Traffic bisa diarahkan ke server terdekat secara geografis (Geo-Load Balancing).

<span id="bab3-5"></span>

### 3.5 ALGORITMA LOAD BALANCING

**A. Round Robin (RR)**

Setiap server menerima request secara bergantian.

```
Server 1 → Request 1
Server 2 → Request 2
Server 3 → Request 3
Server 1 → Request 4
Server 2 → Request 5
```

**Keunggulan:**
- Sederhana
- Adil secara rotasi

**Kekurangan:**
- Tidak memperhatikan beban server

---

**B. Least Connections**

Request dikirim ke server dengan koneksi paling sedikit.

```
Server 1 (5 koneksi)
Server 2 (3 koneksi) → Pilih server 2 (paling sedikit)
Server 3 (4 koneksi)
```

**Keunggulan:**
- Memperhatikan beban
- Lebih adil

**Kekurangan:**
- Tidak memperhatikan resource
- Kompleksitas lebih tinggi

---

**C. Weighted Round Robin (WRR)**

Server dengan weight lebih tinggi menerima lebih banyak request.

```
Server 1 (Weight 3) → 3 request
Server 2 (Weight 2) → 2 request
Server 3 (Weight 1) → 1 request
```

**Keunggulan:**
- Memperhatikan kapasitas server
- Fleksibel

**Kekurangan:**
- Konfigurasi manual
- Tidak adaptif

---

**D. Weighted Least Connections**

Kombinasi Least Connections dengan Weight.

```
Server 1 (Weight 3, 5 koneksi) = 5/3 = 1.67
Server 2 (Weight 2, 3 koneksi) = 3/2 = 1.50 → Pilih server 2
Server 3 (Weight 1, 4 koneksi) = 4/1 = 4.00
```

**Keunggulan:**
- Memperhatikan beban dan kapasitas
- Lebih akurat

**Kekurangan:**
- Kompleks
- Membutuhkan monitoring

---

**E. IP Hash**

Request dari IP yang sama selalu diarahkan ke server yang sama.

```
Client IP 192.168.1.10 → Hash → Server 1
Client IP 192.168.1.20 → Hash → Server 2
Client IP 192.168.1.30 → Hash → Server 3
```

**Keunggulan:**
- Session persistence
- Sederhana

**Kekurangan:**
- Tidak adil jika banyak IP
- Tidak mempertimbangkan beban

---

**F. Random**

Request dikirim ke server secara acak.

**Keunggulan:**
- Sederhana
- Distribusi acak

**Kekurangan:**
- Tidak dapat diprediksi
- Tidak adil

---

**G. Least Response Time**

Request dikirim ke server dengan response time tercepat.

**Keunggulan:**
- Performa optimal
- Adaptif

**Kekurangan:**
- Membutuhkan monitoring
- Kompleks

---

**Perbandingan Algoritma:**

| Algoritma | Keunggulan | Kekurangan | Penggunaan |
|-----------|------------|------------|------------|
| Round Robin | Sederhana | Tidak adil | Server seragam |
| Least Connections | Memperhatikan beban | Tidak perhatikan resource | Beban bervariasi |
| Weighted RR | Perhatikan kapasitas | Manual | Server berbeda |
| Weighted LC | Akurat | Kompleks | Server berbeda |
| IP Hash | Session persistence | Tidak adil | Session sticky |
| Random | Sederhana | Tidak dapat diprediksi | Testing |

### 3.13 ANALISIS MASALAH LOAD BALANCING

**Masalah 1: Server Tidak Sehat (Health Check Gagal)**

| Gejala | Penyebab | Solusi |
|--------|----------|--------|
| Server tidak menerima traffic | Health check gagal | Perbaiki health check |
| Server di-backend tidak accessible | Port tertutup | Buka port |
| Response timeout | Server overload | Tambah resource |

**Solusi:**
```nginx
# Nginx - periksa status upstream
server {
    location /status {
        stub_status;
    }
}

# HAProxy - periksa statistik
# http://haproxy_ip:9000/stats
```

---

**Masalah 2: Session Tidak Persistent**

| Gejala | Penyebab | Solusi |
|--------|----------|--------|
| Pengguna logout tiba-tiba | Session tidak persistent | Aktifkan session persistence |
| Data hilang | Request ke server berbeda | Gunakan ip_hash atau cookie |

**Solusi Nginx:**
```nginx
upstream backend {
    ip_hash;
    server 192.168.1.10:80;
    server 192.168.1.20:80;
}
```

**Solusi HAProxy:**
```haproxy
backend web_backend
    cookie SERVERID insert indirect nocache
    server server1 192.168.1.10:80 cookie server1 check
    server server2 192.168.1.20:80 cookie server2 check
```

---

**Masalah 3: Load Balancing Tidak Merata**

| Gejala | Penyebab | Solusi |
|--------|----------|--------|
| Satu server overload | Algoritma tidak tepat | Ganti algoritma |
| Weight tidak sesuai | Kapasitas berbeda | Sesuaikan weight |
| Traffic tidak seimbang | Konfigurasi salah | Cek konfigurasi |

---

**Masalah 4: SSL/TLS Issues**

| Gejala | Penyebab | Solusi |
|--------|----------|--------|
| SSL error | Certificate tidak valid | Perbaiki certificate |
| HTTPS tidak berfungsi | SSL termination salah | Periksa konfigurasi SSL |

```conf
# Di squid.conf
# Limit bandwidth per klien

delay_class 2 2
delay_parameters 2 50000/100000 20000/100000
delay_access 2 allow browsing
```

```bash
# Menandai traffic dari Squid
```

```nginx
}
```

### 4.3 INTEGRASI MANAJEMEN BANDWIDTH DENGAN LOAD BALANCING

**A. Mengapa Integrasi Diperlukan?**

Manajemen bandwidth dan load balancing dapat diintegrasikan untuk:
1. Mendistribusikan bandwidth ke server yang berbeda
2. Memprioritaskan traffic di setiap server
3. Mengoptimalkan penggunaan bandwidth di semua jalur

---

**B. Arsitektur Integrasi**

```
[Klien] → [Load Balancer] → [Server1] → [QoS]
                          → [Server2] → [QoS]
                          → [Server3] → [QoS]
```

---

**C. Konfigurasi Nginx dengan QoS**

```nginx
http {
    upstream backend {
        server 192.168.1.10:80;
        server 192.168.1.20:80;
        server 192.168.1.30:80;
    }

    # Limit bandwidth per client
    limit_rate_after 1m;
    limit_rate 100k;

    # Limit connections
    limit_conn_zone $binary_remote_addr zone=addr:10m;
    limit_conn addr 10;

    server {
        listen 80;
        location / {
            proxy_pass http://backend;
            # Bandwidth limit
            limit_rate 50k;
            # Untuk download besar
            location /download/ {
                limit_rate 200k;
            }
        }
    }
}
```

---

**D. Konfigurasi HAProxy dengan QoS**

```haproxy
frontend web_frontend
    bind *:80
    # Rate limiting
    rate-limit sessions 100
    rate-limit connections 10
    default_backend web_backend

backend web_backend
    # Round Robin dengan weight
    balance roundrobin
    server server1 192.168.1.10:80 weight 3 check
    server server2 192.168.1.20:80 weight 2 check
    server server3 192.168.1.30:80 weight 1 check
```

```
         │
```

**A. Proxy Server Configuration (Squid)**

```conf
# /etc/squid/squid.conf
# HTTP Port
http_port 3128

# ACL
acl localnet src 192.168.1.0/24
acl workhours time MTWHF 08:00-17:00
acl business dstdomain .company.com
acl business dstdomain .erp.company.com

# Allow business always
http_access allow business

# Allow localnet during workhours
http_access allow localnet workhours

# Deny others
http_access deny all

# Cache
cache_dir ufs /var/spool/squid 5000 16 256
cache_mem 512 MB
maximum_object_size 100 MB

# Bandwidth limitation per user
delay_pools 2
delay_class 1 2
delay_parameters 1 50000/100000 20000/100000
delay_access 1 allow localnet

# Logging
access_log /var/log/squid/access.log
```

**B. Load Balancer Configuration (HAProxy)**

```haproxy
# /etc/haproxy/haproxy.cfg
global
    log /dev/log local0
    maxconn 10000
    user haproxy
    group haproxy
    daemon

defaults
    log global
    mode http
    option httplog
    option dontlognull
    retries 3
    timeout connect 5000
    timeout client 50000
    timeout server 50000

# Load balancer untuk proxy
frontend proxy_frontend
    bind *:8080
    default_backend proxy_backend

backend proxy_backend
    balance leastconn
    option httpchk GET /squid-internal-mgr/
    server proxy1 192.168.1.10:3128 check weight 3
    server proxy2 192.168.1.20:3128 check weight 2
    server proxy3 192.168.1.30:3128 check weight 1

# Load balancer untuk web server
frontend web_frontend
    bind *:80
    bind *:443 ssl crt /etc/ssl/certs/company.pem
    default_backend web_backend

backend web_backend
    balance roundrobin
    cookie SERVERID insert indirect nocache
    server web1 192.168.2.10:80 cookie web1 check
    server web2 192.168.2.20:80 cookie web2 check
    server web3 192.168.2.30:80 cookie web3 check
```

**C. Manajemen Bandwidth (Linux tc)**

```bash
#!/bin/bash
# bandwidth-mgmt.sh

DEV="eth0"
RATE="100mbit"

# Clear existing
tc qdisc del dev $DEV root 2>/dev/null

# Root qdisc
tc qdisc add dev $DEV root handle 1: htb default 40

# Root class
tc class add dev $DEV parent 1: classid 1:1 htb rate $RATE ceil $RATE

# Classes untuk berbagai traffic
# VoIP (prioritas tinggi)
tc class add dev $DEV parent 1:1 classid 1:10 htb rate 10mbit ceil 20mbit prio 0

# Business apps (prioritas sedang)
tc class add dev $DEV parent 1:1 classid 1:20 htb rate 30mbit ceil 50mbit prio 1

# Browsing (prioritas normal)
tc class add dev $DEV parent 1:1 classid 1:30 htb rate 40mbit ceil 60mbit prio 2

# Other (prioritas rendah)
tc class add dev $DEV parent 1:1 classid 1:40 htb rate 20mbit ceil 30mbit prio 3

# Filters
# VoIP (DSCP EF)
tc filter add dev $DEV parent 1:0 protocol ip prio 1 u32 match ip dscp 0x2e 0xfc flowid 1:10

# Business apps
tc filter add dev $DEV parent 1:0 protocol ip prio 2 u32 match ip dscp 0x22 0xfc flowid 1:20

# HTTP/HTTPS
tc filter add dev $DEV parent 1:0 protocol ip prio 3 u32 match ip dport 80 0xffff flowid 1:30
tc filter add dev $DEV parent 1:0 protocol ip prio 3 u32 match ip dport 443 0xffff flowid 1:30

echo "Bandwidth management configured"
```
